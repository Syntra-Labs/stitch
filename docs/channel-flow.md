# DataChannel application flow

Stitch remains a browser WebRTC application, not an SCTP/DTLS implementation. ICE, DTLS authentication of the channel endpoint, SCTP delivery, congestion control, fragmentation and association behavior belong to the browser. This adapter does not independently authenticate a peer's advertised mesh identifier. Real browser/network interoperability still requires qualification.

New reliable ordered channels advertise the DataChannel protocol `stitch.channel/1`. Existing small JSON messages, including heartbeat probes, Ethernet arrays and storage messages, keep their wire and logical forms. Legacy channels with an empty protocol can exchange those messages but reject messages exceeding their negotiated single-message capacity with `channel-peer-framing-unsupported` rather than claim unsupported delivery.

`RTCSctpTransport.maxMessageSize` limits every `send()`. An absent value uses the RFC8841 65536-byte default. Zero or infinity means no negotiated bound, while the application's 65536-byte scheduling quantum still applies. A logical JSON envelope remains bounded at 524288 UTF-8 bytes, preserving the existing maximum 128KiB storage object's JSON representation. A message larger than the wire quantum is split into ArrayBuffers. Each has four network-order uint32 fields: magic `0x53544331` (STC1), monotonically increasing per-channel message ID, total UTF-8 byte length, and byte offset, followed by payload. Wire capacity of 16 bytes or less cannot carry fragmented payload and is explicitly refused. This is an application version, not a standardized external protocol.

Only reliable ordered channels use fragmentation. Each channel assembles one message at a time, requires contiguous offsets and consistent ID/total, and rejects duplicates, interleaving, replay, malformed UTF-8, invalid strict JSON and oversize envelopes. Framing errors poison and close that channel; incomplete envelopes never reach the application. DTLS/SCTP already supplies channel integrity. Object commitments and signatures remain checked by their existing application owners; framing does not add or replace a cryptographic authenticity claim.

Across one transport node, queued logical payloads are limited to 64 messages and 2MiB UTF-8 bytes. Concurrent incomplete receive assemblies are limited to 16 and 2MiB. Each browser channel is permitted at most 1MiB of buffered application bytes, with `bufferedAmountLowThreshold` set to 512KiB. FIFO queues resume on `bufferedamountlow`; one bounded wire frame is materialized at a time. These are application payload budgets, not a measurement or bound of JavaScript object/string overhead, browser internals, TLS, SCTP or ICE memory. Messages and assemblies expire after 30 seconds measured locally. Expiration closes the stream rather than silently skipping a partial message.

Admission atomically charges all frame headers and payload bytes before enqueue. Failed/unknown work is not refunded. Deferred sends recheck lifecycle, peer/channel generation, consent callbacks and the captured resource epoch before each frame. VM Ethernet uses a consent callback so queued frames cannot survive grant withdrawal. Closing/replacing a channel or transport releases queue/assembly reservations; a new channel never inherits or automatically replays a partial message.

`sendToPeer` true and the broadcast count mean local queue acceptance. `channel_send_result` distinguishes `submitted` (browser accepted every frame, **not recipient delivery**), `cancelled`, `partial`, `unknown`, `incomplete-receive`, and `closed`, with a reason. Submit exceptions with no accepted frame are unknown; after accepted frames they are partial. Final remote processing cannot be inferred from these local observations. C1 heartbeat correlation begins only after complete browser submission, not while waiting in the local queue.

`Stitch.ChannelFlow` is the runtime-bound numeric queue/send admission and ordered append transition model. Its stale-send theorem concerns that transition only. Host parser, browser behavior, scheduling and physical connectivity are separate test/qualification obligations.
