# Operator experience projection

`app/src/Product/Experience.lex.tex` owns six browser journeys: mesh disclosure and joining; objects, placement and recovery; deterministic pure jobs; host VM effects; pinned pointers and publication reconciliation; and application resource policy.

This is the real `index.html` operator interface, not a separate probe. The existing strict project-owned source adapter explicitly selects `Product.Experience` alongside the Stitch domain modules. Its generated definitions in `src/layer1-uor/generated-model.js` supply the actual journey metadata, view selectors, evidence labels, action guards, named evidence palette, navigation visibility, focus policy and explanation-disclosure policy. Unsupported source syntax and stale generated bytes fail the source check. This adapter is not LexLean, a proof compiler or a host certificate.

`src/product-experience.js` is the handwritten DOM adapter. It reads existing domain/runtime observations; it does not add an effect ledger, resource ledger, custody history or publication journal. `index.html` binds the same model action predicates both to disabled buttons and to the handlers, so a forced click cannot bypass readiness. The real adapters still enforce exact resource costs and domain preconditions before effects.

## Information in context

- Only the selected journey panel is visible. Moving between journeys retains form edits and runtime state. Native navigation buttons support Enter/Space, move focus only on explicit navigation and never overwrite the URL's mesh-key hash. Scrolling is nonanimated, including for reduced-motion users.
- View summaries use polite, atomic live announcements. Unchanged status does not announce again on every timer tick. Named status colors have tested text contrast on the current dark panel surface; the status wording carries meaning without color.
- Detailed evidence explanations are disclosures. The model initially opens them when first-use signaling disclosure, unknown publication or resource-policy review needs attention. Other explanations remain available on request. Asynchronous observations do not steal navigation or focus.
- Public signaling requires explicit disclosure acceptance and an explicit join. Acceptance alone does not connect; withdrawing it closes the mesh. Public object/job relay disclosure is a separate opt-in.
- Provider publication setup appears after a pinned authority and a relevant object/head. A separate reconciliation action replaces new publication while an exact scoped candidate is unresolved. Unknown state opens its explanation and reconciliation controls.
- Guest command controls appear only after an observed ready VM lifecycle. A guest-output object digest is not execution certification. Pure-job replay evidence remains distinct.
- Scheduler estimates, external inspection commands and experimental benchmarks are contextual diagnostics, not first-use readiness gates. Benchmarks do not run on startup.
- Resource attention is not a second admission system. Exhausting one dimension or refusing an expensive operation does not globally prohibit later cheaper work. The exact runtime vector remains authoritative. Expired epochs, full reservation capacity and clock regression block global application admission; inspection/export/explicit renewal remain available.

## Evidence scope

Local object integrity is distinct from conditional, digest-checked peer assertions. Peer identifiers do not establish independent machines, honest retention or reachability. Pure-job aggregate replay status requires every relevant unfinished job to have replay evidence; a completed replayed job cannot mask an unverified unfinished job. A retained local pointer head is not a DNS publication receipt. A confirmed provider record is not global DNS ordering or resolver propagation. An open peer channel is not full WebRTC/NAT certification. Neither a successful join nor a C1 benchmark is a barrier to ordinary local use.

The module includes finite, kernel-checkable safety witnesses and universally quantified Boolean gate properties for disclosure, guest readiness, unknown publication and blocked budgets. The project-owned projection tests are separate implementation-conformance checks, including a mutation test proving that changing Experience source changes the real generated labels and guards. Neither kind of evidence certifies the whole browser, OS, network, VM or physical host.

## Checks and remaining boundaries

Focused checks:

- `node --test tests/product-experience.test.js tests/runtime-admission.test.js`
- `node scripts/check-model.mjs`
- `node scripts/check-product.mjs --check`
- Actual `lexlean fmt`, `lock`, `check` and `verify` against the official pinned toolchain. The final project closure, not this projection, owns release assurance.

The surrounding DOM snapshot extraction, markup, layout, spacing, typography, input grouping, advanced-diagnostic copy and table rendering remain handwritten. Do not infer full presentation correspondence or a complete standards implementation from this journey model. The executed-script test harness exercises the actual inline browser script but is not a real graphical browser or physical WebRTC/provider trial.

Operational follow-up identified from the current stack, pending standards-scope reconciliation: an obvious browser object-evidence export path for the independent verifier; trusted recent-anchor import/export after pointer head loss; durable authority/key lifecycle; and provider-token setup/replacement guidance. These are separate from the implemented session-only contracts and must not be implied by the interface.
