# Operator experience projection

`app/src/Product/Experience.lex.tex` owns six browser journeys: mesh disclosure and joining; objects, placement and recovery; deterministic pure jobs; host VM effects; pinned pointers and publication reconciliation; and application resource policy.

This is the real `index.html` operator interface, not a separate probe. The existing strict project-owned source adapter explicitly selects `Product.Experience` alongside the Stitch domain modules. Its generated definitions in `src/layer1-uor/generated-model.js` supply the actual journey metadata, view selectors, evidence labels, action guards, named evidence palette, navigation visibility, focus policy and explanation-disclosure policy. Unsupported source syntax and stale generated bytes fail the source check. This adapter is not LexLean, a proof compiler or a host certificate.

`src/product-experience.js` is the handwritten DOM adapter. It reads existing domain/runtime observations; it does not add an effect ledger, resource ledger, custody history or publication journal. `index.html` binds the same model action predicates both to disabled buttons and to the handlers, so a forced click cannot bypass readiness. The real adapters still enforce exact resource costs and domain preconditions before effects.

## Information in context

- Only the selected journey panel is visible. Moving between journeys retains form edits and runtime state. Native navigation buttons support Enter/Space, move focus only on explicit navigation and never overwrite the URL's mesh-key hash. Scrolling is nonanimated, including for reduced-motion users.
- Every input has a persistent associated visible label. Instructions describe byte/step bounds, scope, trust and disclosure beside the relevant controls. Contextual polite result/error regions retain the wire log and its details rather than replacing evidence with color. Action descriptions preserve authored explanation references. View summaries use polite, atomic live announcements. Unchanged status does not announce again on every timer tick. Named status colors have tested text contrast on the current dark panel surface; the status wording carries meaning without color.
- Detailed evidence explanations are disclosures. The model initially opens them when first-use signaling disclosure, unknown publication or resource-policy review needs attention. Other explanations remain available on request. Asynchronous observations do not steal navigation or focus.
- Public signaling requires explicit disclosure acceptance and an explicit join. Acceptance alone does not connect; withdrawing it closes the mesh. Public object/job relay disclosure is a separate opt-in.
- Provider publication setup appears after a pinned authority, including after a reload with no object or observer-head RAM. Loading a saved write must not require volatile object state. A separate reconciliation action replaces new publication while an exact scoped candidate is unresolved. Unknown state opens its explanation and reconciliation controls.
- Guest command controls appear only after an observed ready VM lifecycle. Captured stdout/stderr has a bounded, keyboard-scrollable UTF-8 text preview before object storage is attempted. A command selector exposes every retained handle, including an earlier unknown result, through the same per-command admission predicates. Selection never dispatches or replays a command. Forgetting resolved evidence also clears its displayed preview. A guest-output object digest is not execution certification. Pure-job replay evidence remains distinct.
- Scheduler estimates, external inspection commands and experimental benchmarks are contextual diagnostics, not first-use readiness gates. Benchmarks do not run on startup.
- Resource attention is not a second admission system. Exhausting one dimension or refusing an expensive operation does not globally prohibit later cheaper work. The exact runtime vector remains authoritative. Expired epochs, full reservation capacity and clock regression block global application admission; inspection/export/explicit renewal remain available.

## Evidence scope

Local object integrity is distinct from conditional, digest-checked peer assertions. Peer identifiers do not establish independent machines, honest retention or reachability. Pure-job aggregate replay status requires every relevant unfinished job to have replay evidence; a completed replayed job cannot mask an unverified unfinished job. A retained local pointer head is not a DNS publication receipt. A confirmed provider record is not global DNS ordering or resolver propagation. An open peer channel is not full WebRTC/NAT certification. Neither a successful join nor a C1 benchmark is a barrier to ordinary local use.

The module includes finite, kernel-checkable safety witnesses and universally quantified Boolean gate properties for disclosure, guest readiness, unknown publication and blocked budgets. The project-owned projection tests are separate implementation-conformance checks, including a mutation test proving that changing Experience source changes the real generated labels and guards. Neither kind of evidence certifies the whole browser, OS, network, VM or physical host.

## Restart, scope and recovery

Saved authority setup/restore and the write-ahead publication journal are origin-local mechanisms. They are not backups, key rotation, or private-key export/import. After a reload, explicitly pin the original saved key, use the exact DNS name and Cloudflare zone, then load saved publication. A token is needed for reconciliation reads, not for loading the journal. Unknown writes retain the exact candidate; changing name, key or zone selects another scope rather than resolving an earlier write. Journal/store failures do not establish absence or authorize another candidate. The interface explains scoped token replacement without retaining its value.

Object/job export/import and explicitly accepted recent-anchor evidence are available through the recovery journey. They do not restore signing keys, provider-write journals or the running DNS observer's retained head. Export selection is retained across panel reopening; new entries are not silently added to a previous selection. Imported selectors retain an available choice and explicitly identify empty evidence sets. Editing the selected anchor, independently trusted key or digest clears the corresponding acceptance checkbox.

## Qualification still required

The new label/instruction checks are static markup checks. Executed-script and synthetic-DOM tests cover refusal feedback, interrupted storage, replay/import state, saved-write access with no object RAM, retained-command selection and text output when caching fails. They do not establish WCAG compliance, browser accessibility-tree correctness, visual reflow, screen-reader announcements, native file/download or clipboard behavior, or real IndexedDB/Web Locks interoperability. The graphical VM display can contain graphics-only applications with no equivalent text. The shell command/output path is a text alternative for the operations this UI exposes, not an accessibility certification of arbitrary guest software.

A prior Chromium launch was blocked by the execution environment's Unix-socket restriction. No browser launch or alternative bypass was attempted in this change. Real graphical/browser and assistive-technology qualification remains outstanding, along with provider/WebRTC/physical-host trials and the final exact-source/native-artifact gates. A recent-anchor acceptance in the separate recovery vault deliberately does not grant the live observer a new head; live continuation after total head loss still requires an explicitly modeled and authorized trust-bootstrap path.
